# F2 — Runtime Execution and Streaming Boundary

Agent Graph is no longer owned by F2. OCTO v5 treats the visible `Agency → Department → Workspace → Agent` graph, its minimum CRUD, hierarchy validation and operational state projection as the **F1 Agent Graph System**.

## F2 boundary

F2 starts after the F1 graph is already persisted, navigable and guarded. F2 must not be used to relabel the F1 graph work; it is reserved for capabilities that require runtime behavior beyond the persisted hierarchy, such as:

- real agent execution beyond Control Plane CRUD;
- runtime status/event projections fed by execution workers;
- streaming execution updates;
- multi-agent runtime coordination beyond the F1 hierarchy model.

## Compatibility note

The legacy `scripts/f2-agent-graph-smoke.sh` entrypoint remains as a wrapper so older automation does not break, but it delegates to `scripts/f1-agent-graph-smoke.sh` and prints that Agent Graph is validated as F1. New automation should use `pnpm f1:agent-graph-smoke` or the full `pnpm f1:close-gate`.
