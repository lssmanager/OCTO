# F2 — Agent Registry & Hierarchy System

F2 makes the `Agency → Department → Workspace → Agent` hierarchy visible, persisted and operable without turning OCTO into a flow engine or visual DAG editor. SubAgent, multi-agent runtime coordination, flow editing and real runtime status streams remain deferred to later phases.

## Implemented F2 slice: Agent Graph Console

- `apps/web` uses `/` as the **Agent Graph Console** and keeps the former foundation status dashboard available at `/status`.
- The console projects Control Plane state only: it can request node/agent mutations, but hierarchy validation and persistence are performed by `apps/api`.
- `apps/api/src/agents` exposes graph and node endpoints under `/v1/agents` and reuses `PostgresAgentRepo` with `agents`, `agent_versions` and `hierarchy_nodes`.
- The persisted hierarchy supports `Agency`, `Department`, `Workspace` and `Agent` for this F2 closure. `SubAgent` remains supported by lower-level contracts where present, but is not part of the minimum UI scope.

## API surface

Authenticated users with `agents:read` can query:

- `GET /v1/agents/graph` — nested hierarchy projection with agent links, local policies, effective policies, capabilities and explicit `runtimeStatus: null` when unavailable.
- `GET /v1/agents/nodes/:nodeId` — detail projection for a hierarchy node.

Authenticated users with `agents:write` can mutate:

- `POST /v1/agents/nodes` — create Agency/Department/Workspace nodes.
- `PATCH /v1/agents/nodes/:nodeId` — update node name, activation and first-slice policy columns.
- `PATCH /v1/agents/nodes/:nodeId/parent` — move a node under a valid parent.
- `POST /v1/agents` — create an Agent and its linked `hierarchy_nodes` row under a Workspace.
- `PATCH /v1/agents/:id` — update an Agent and its linked hierarchy node where applicable.

## Validation and boundaries

- Tenant isolation stays an auth/storage concern (`tenant_id`, guards and RLS); it is not modeled as a cognitive hierarchy level.
- Valid F2 relationships are: root `Agency`, `Agency → Department`, `Department → Workspace`, `Workspace → Agent`.
- Effective policies are compiled in the Control Plane from the persisted hierarchy chain and returned to the UI as a projection.
- Runtime online/offline data is not invented. Until a mature runtime event projection exists, the console displays runtime status as unavailable and supports manual refresh/polling-style updates.
