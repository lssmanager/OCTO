# F1 — Agent Graph System and Foundation Kernel

## 1. Executive Summary

F1 closes the operational foundation plus the OCTO v5 **Agent Graph System**. The graph scope is explicit and limited: make `Agency → Department → Workspace → Agent` visible, persisted, guarded and operable through minimum CRUD and state projection.

F1 does **not** include real agent execution, runtime streaming, flow editing, SubAgent runtime orchestration or F2/F3 execution behavior. Runtime fields may be projected only as honest operational state; they must not be invented by the UI.

## 2. Definition of Done

F1 is COMPLETE only when all of these are true:

- foundation services build, deploy and report real health: API, PostgreSQL, Redis, LiteLLM gateway visibility and workers/queues where configured;
- the web console exposes the **F1 Agent Graph Console** at `/` and keeps foundation status available at `/status`;
- authenticated graph reads use server-side credentials or a session-aware backend path, not browser-public secrets;
- console writes go through the web backend route/session-aware proxy and then through `apps/api` JWT/RBAC/tenant/hierarchy guards;
- CRUD smoke covers `Agency → Department → Workspace → Agent` with persistence;
- expected error paths are validated: missing credentials, invalid hierarchy and cross-tenant/nonexistent node access;
- `pnpm f1:close-gate` validates Agent Graph as F1 and does not print “F2 close” for this capability.

## 3. F1 Agent Graph Scope

Included in F1:

- persisted hierarchy levels: `Agency`, `Department`, `Workspace`, `Agent`;
- valid relationships: root `Agency`, `Agency → Department`, `Department → Workspace`, `Workspace → Agent`;
- `GET /v1/agents/graph` nested graph projection;
- `GET /v1/agents/nodes/:nodeId` node detail projection;
- `POST /v1/agents/nodes` for Agency/Department/Workspace creation;
- `POST /v1/agents` for Agent creation under a Workspace;
- patch/reparent endpoints where already guarded by backend policy;
- effective policy/capability projection from the persisted chain;
- explicit `runtimeStatus: null`/unavailable when runtime projection does not exist.

## 4. Secure Console Model

The browser must never hold an OCTO write token through a `NEXT_PUBLIC_*` variable. The console uses a same-origin backend route at `apps/web/src/app/api/agent-graph/route.ts`:

- reads require server-side `OCTO_WEB_CONSOLE_TOKEN` and call `GET /v1/agents/graph` from the server;
- writes require either an `httpOnly` `octo_console_token` session cookie or explicit development/smoke opt-in with `OCTO_WEB_CONSOLE_ALLOW_SERVER_TOKEN_WRITES=true` plus server-side `OCTO_WEB_CONSOLE_TOKEN`;
- the route only allows named Agent Graph actions and forwards them to the existing API endpoints, preserving backend JWT/RBAC/tenant/hierarchy guards.

Production deployments should prefer a real session cookie. The server-token write mode is for controlled internal/dev/smoke environments and must not be represented as a browser secret.

## 5. Out of Scope for F1

F1 does not include:

- real agent execution;
- streaming runtime responses;
- runtime status feeds beyond honest unavailable/null projections;
- visual DAG/flow editing;
- SubAgent runtime orchestration;
- durable tool calling beyond existing foundation contracts;
- semantic memory/RAG;
- external channels.

## 6. Validation

Use these commands for the graph slice and close gate:

- `pnpm --filter @octo/api test -- src/agents/agent-graph.integration.test.ts` validates service-level persistence and effective projections.
- `pnpm f1:agent-graph-smoke` validates API-level CRUD and expected error paths against a running API.
- `pnpm f1:close-gate` runs the strict F1 close gate, including the F1 Agent Graph smoke.
